# 059 — Encrypted chat backups
**Status:** accepted 2026-10-08 (root), contract v1.22 §22. P0-2 (disappearing chats).

## Context
Reinstalls lose every chat: the in-app update fails, testers uninstall, `allowBackup` is false and
MLS state is never restorable. History sharing (§17) needs another device that still holds the
chats and worked for 7 of 29 pilot requests. §17.14 reserved a client-encrypted backup built on
the §17.7 bundle.

## Decision
- **Unit:** the §17.7 bundle with `origin: "backup"` plus conversation/chat-state, tombstone,
  group-event and contact lines; imported through the §17.7 path, not bound to the gap index or 30
  days. Restore = messages and chat state; the device rejoins as a new leaf.
- **Keys:** a random per-account `BK` (local in `mls_kv` under the Keystore-wrapped DB key, so
  daily backups run unattended); a recovery copy wrapped under Argon2id(64 MiB, t 3, p 1) of a
  120-bit recovery key (7×4 Crockford characters with a checksum) and optionally a passphrase with
  a floor; HKDF-separated wrap key plus a 16-byte key check; AAD bound to user, kind and `bk_id`.
  A fresh `DEK` per backup. Fixed KDF parameters in v1.
- **Format:** `RISIMEBK` v1, the same for server, local and exported backups; AES-256-GCM STREAM
  (64 KiB chunks, index and last flag in nonce and AAD, header hash in every chunk); raw DEFLATE
  then Padmé. The header carries the key record, so a file restores with the recovery secret alone.
- **Server:** blob purpose `backup` (owner-only, ≤ 16 parts of 32 MiB, 512 MiB per backup), newest
  2 current, replaced kept 7 days (≤ 5), 1.5 GiB live, 6 backups a day; one backup device per
  account; no silent key change; switch `BACKUPS` (off stops writes only).
- **When:** server daily; local daily, before every in-app update, before any confirmed wipe; no
  server backup from a fresh install before restore or skip. Turning on is a user step (the
  recovery key); local backups are automatic.
- **No full-size images in v1** (by reference with thumbnail and key; originals for 30 days).
- **New dependencies:** RustCrypto `argon2` in the core; Android uses the platform
  `java.util.zip.Deflater/Inflater` (no library). Vectors: `contract/v1/backup_vectors.json`,
  generated by the core and an independent `scripts/gen-backup-vectors`.

## Consequences
- A user who never turns on server backup is still lost on uninstall; the app asks after the
  update and keeps a card, and warns "Don't uninstall" when an update fails.
- A forgotten recovery key (and passphrase) means the server backups are unreadable: "Reset backup
  key" deletes them. Root's upgrade gate gains an "uninstall, reinstall, restore" scenario.
- The server learns backup times, sizes and devices, never content or keys; the wrapped `BK` is
  offline-attackable by its holder (hence 120 bits and the passphrase floor).

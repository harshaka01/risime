# 071 — Self-hosted speech-to-text for Risi call transcription (faster-whisper on 127.0.0.1:8200)
**Status:** accepted 2026-10-09 (root); **amended 2026-10-12** (a, b; c = Sinhala route from the held-out ASR eval) (multi-model routing for Sinhala and
Tamil, new memory numbers: see "Amendment 2026-10-12" at the end, which overrides the image tag,
default compute type, allocator and memory numbers above). Implements the infra part of decision 070 (§27.7–27.9:
Risi listening to Official calls). The speech model is named in `made_by.also` as
`faster-whisper-large-v3` (provider `risime`, task `transcribe`).

## Decision
- **Engine:** faster-whisper 1.2.1 on CTranslate2 4.8.2, **built from source with CUDA for the
  GB10** (sm_121, aarch64). PyPI's aarch64 `ctranslate2` wheels are CPU-only.
  - **Build flags:** `-gencode=arch=compute_121,code=sm_121` is patched in, because CMake's
    FindCUDA arch table doesn't know 12.1. The build uses `WITH_CUDNN=OFF`, `WITH_MKL=OFF`
    and `WITH_RUY=ON`.
  - **Why no cuDNN:** CTranslate2's cuDNN Conv1D uses the legacy API with fixed algorithms, and
    cuDNN 9.26 answers `CUDNN_STATUS_NOT_SUPPORTED` on sm_121. Without cuDNN, CTranslate2 uses its
    own im2col + cuBLAS Conv1D. Whisper has only two conv layers, so this costs nothing measurable.
  - **`av==15.1.0` is pinned**, because PyAV 16+ dropped the `metadata_errors` argument that
    faster-whisper 1.2.1 passes.
- **Image:** `risime/whisper:ct2-4.8.2-fw-1.2.1`, built locally by
  `infra/whisper/Dockerfile`, in two stages, on `nvcr.io/nvidia/vllm:26.09-py3`. That base has
  CUDA 13.4, Python 3.12 and ffmpeg.
  - **Why this base:** it is already on spark2 for `risi-l1` (decision 061). Its layers are
    shared, so the image adds about 0.3 GB of disk, not 26 GB, and needs no new pull. It also
    carries the build toolchain and vLLM's Whisper serving (the fallback below).
  - **Server:** `infra/whisper/server.py`, a small FastAPI app.
- **API** (OpenAI-compatible):
  - `POST /v1/audio/transcriptions` takes multipart `file`, `model`, `language`, `prompt`,
    `response_format` (`json`, `text` or `verbose_json`), `temperature`, and `vad_filter` (an
    extension, default true).
    - `verbose_json` adds `language_probability`, `duration`, `duration_after_vad`, `segments`
      (with `avg_logprob` and `no_speech_prob`) and `processing_s`.
    - `model` must be the alias or `whisper-1`.
  - `GET /v1/models` (with the key) lists the alias.
  - `GET /health` needs no key.
  - Every other call needs `Authorization: Bearer $WHISPER_API_KEY`. The key lives in `.env`,
    is generated by `scripts/whisper-smoke --init-key` (or was added by root on spark2) and is
    never printed.
  - The upload limit is 25 MB.
- **Model:** `large-v3` as CTranslate2 float16 (`Systran/faster-whisper-large-v3`, MIT), in
  `~/risime-models/faster-whisper-large-v3`, mounted read-only.
  - The alias `faster-whisper-large-v3` is served.
  - Beam size is 5. `condition_on_previous_text` is off, because calls arrive as ≤ 30 s chunks.
  - The Silero VAD filter is on.
  - **Faster option:** `large-v3-turbo` (`mobiuslabsgmbh/faster-whisper-large-v3-turbo`, MIT,
    already in `~/risime-models/faster-whisper-large-v3-turbo`).
    - Measured on the JFK clip: 0.38 s against 0.72 s for large-v3, with the same English text.
      It is about 1.4 GB smaller.
    - Its Sinhala and Tamil are expected to be no better.
    - To switch, set `WHISPER_MODEL_DIR=faster-whisper-large-v3-turbo` and
      `WHISPER_MODEL_ALIAS=faster-whisper-large-v3-turbo` in `.env`, then `up -d`. The alias is
      what `made_by` and the learning log show, so it must name the real model.
  - `WHISPER_COMPUTE_TYPE=int8_float16` gave the same English text, at 0.69 s, with less memory.
- **Network and privacy:**
  - `127.0.0.1:8200` only (rule 6), with no Caddy route. The only client is the app server's
    `risi-listen` path.
  - `HF_HUB_OFFLINE=1` and a local model path (`local_files_only`) mean nothing is fetched at
    runtime.
  - Audio is decoded in memory and never written. `/tmp` is a 256 MB tmpfs.
  - The root filesystem is read-only. The service runs as uid 1000, with `cap_drop: ALL` and
    `no-new-privileges`.
  - The access log is off, and faster-whisper's own logger is at WARNING. The service logs
    metrics only: audio seconds, processing seconds, detected language and segment count. It
    never logs text or prompts (decision 066).
  - The container stays on the default bridge network, because an `internal` network can't
    publish a port. It makes no outbound calls.
- **Concurrency:** `WHISPER_NUM_WORKERS=2`, so two transcriptions run in parallel on the GPU and
  more requests queue. With `RISI_LISTEN_MAX=4`, this is enough (see the latency numbers below).

## Memory (measured on spark2, 2026-10-09, next to the running vLLM `risi-l1` at 0.34)
| State | `free -m` available | GPU (nvidia-smi, whisper) | container RSS |
|---|---|---|---|
| whisper down | 33 770 MB | — | — |
| whisper up, idle (model loaded) | 28 011 MB | 4 447 MiB | 0.5 GB |
| after smoke + 8 parallel requests | 26 880 MB | 6 553 MiB | 1.1 GB |

- **Total cost:** about **7 GB**, unified memory (GPU and host share the 121 GB).
- **Headroom:** about 27 GB of RAM stays available, which is more than the 24 GB that
  decision 061 asks to keep for the pilot. The two coexist, and `scripts/llm-smoke` passed both
  before and after whisper started, with the same numbers: JSON extraction in 4.3–4.6 s,
  ~4.9k-token summary in 9.4–9.6 s, decode 50.2 tok/s.
- **Limits:**
  - `mem_limit: 6g` caps host-side RAM (Python, decoding, buffers).
  - CUDA allocations on the GB10 are driver-allocated unified memory outside the cgroup, so
    the GPU share is bounded instead by the model size plus CTranslate2's caching allocator.
    That allocator is capped at 1 GiB of freed blocks
    (`CT2_CUDA_CACHING_ALLOCATOR_CONFIG=4,3,12,1073741824`).
- **If memory gets tight:**
  - first switch to `int8_float16` or turbo, which saves about 1.5–3 GB;
  - then stop whisper (`docker compose -f infra/docker-compose.whisper.yml stop`). The server
    then answers `risi: unavailable` (§27.7).

## Latency (measured, `scripts/whisper-smoke` and a parallel test)
- **English** (11.0 s JFK clip, Opus 24 kbit/s): 0.92–0.95 s end to end, RTF 0.085, exact
  transcript. The model loads in 2.7 s, and the container is healthy about 10 s after `up`.
- **Parallel** (11 s clip): 4 requests take 2.45 s wall (max latency 2.44 s); 8 requests take
  4.94 s wall (max 4.94 s). At 4 listened calls with ≤ 30 s chunks this stays far ahead of real
  time.
- **Tamil** (FLEURS `ta_in`, 7.8 s, read speech): 2.6–2.9 s, **CER 12 %**, both with
  `language=ta` and with auto-detect (detected `ta`, p = 0.97). The text is readable; errors are
  mostly vowel signs and consonant confusions (அழைக்கப்படுகிறது → அளைக்கப்படிகிறது).
  Good enough to extract follow-ups from.
- **Sinhala** (OpenSLR SLR30, 5.2 s, read speech): **unusable.**
  - With `language=si`: CER ~100 %, the wrong words, and 5.5 s because of temperature fallbacks.
  - With auto-detect, it detected **Bengali** (p = 0.33) and transcribed into Bengali script.
  - **Consequences:**
    - the app server must pass `language` when it knows it;
    - Sinhala speech should not be summarised from this model;
    - a Sinhala-finetuned Whisper, or a different model, is follow-up work (a decision
      amendment, not a contract change).
- These are single-clip spot checks of read speech. Real call audio (crosstalk, Singlish /
  code-mixing) will be worse.

## How to update
- **Model:** download into `~/risime-models/<dir>` (CTranslate2 format), set `WHISPER_MODEL_DIR`
  and `WHISPER_MODEL_ALIAS` in `.env`, then run
  `docker compose --env-file .env -f infra/docker-compose.whisper.yml up -d` and
  `scripts/whisper-smoke`.
- **CTranslate2 / faster-whisper:** bump `CT2_VERSION` / `FASTER_WHISPER_VERSION` in the
  Dockerfile. Re-check:
  - the sm_121 sed;
  - whether cuDNN Conv1D works (try `WITH_CUDNN=ON`);
  - the `av` pin.

  Then `up -d --build` and run both smokes.
- **Base image:** when `risi-l1` moves to a newer `nvcr.io/nvidia/vllm` tag, move `BASE` with
  it so the layers stay shared, and rebuild.
- `restart: unless-stopped`. The first build takes about 10 minutes (CTranslate2 compile, 20
  cores); later builds use the cache.

## Fallback (as decision 070 allows)
If the CTranslate2 CUDA build breaks on a future base, serve Whisper with vLLM instead:
- `vllm serve /models/whisper-large-v3 --served-model-name faster-whisper-large-v3`, from the same
  NGC image. That needs the HF-format `openai/whisper-large-v3` weights in `~/risime-models`;
  they are not downloaded yet.
- It has the same OpenAI `/v1/audio/transcriptions` endpoint on 127.0.0.1:8200 with
  `VLLM_API_KEY=$WHISPER_API_KEY`, and a small `--gpu-memory-utilization` (~0.06). Re-measure
  next to `risi-l1`.

The alias must then name the real model (e.g. `whisper-large-v3-vllm`). That would be an
amendment to this decision, not a contract change. vLLM's endpoint has no VAD and no
`verbose_json` segment confidences.

| `whisper-large-v3-sinhala` | compare only | `~/risime-eval-models/whisper-large-v3-sinhala` (kasunw) | `faster-whisper-large-v3-sinhala` (CT2 int8_float16) | faster-whisper |

- `infra/whisper/convert_models.py` does the conversions inside the image, CPU only, offline
  (`ct2-transformers-converter` equivalent with `load_as_float16`, `low_cpu_mem_usage`; the fast
  `tokenizer.json` is built locally, else faster-whisper would fetch one).
- **tamil-asr-qwen3** is in Qwen's original layout (`thinker_config`, `thinker.*` weights), which
  transformers' native `Qwen3ASRForConditionalGeneration` doesn't read directly.
  `infra/whisper/qwen3_asr.py` builds the native config, builds the model on the GPU and streams
  the safetensors into it with a key map (the audio projector moves from the audio tower to
  `multi_modal_projector`). No accelerate, no CPU copy: load 1.2 s warm, 7–8 s cold page cache
  (25 s with `from_pretrained` + `.to(cuda)`). Greedy decoding (`QWEN_ASR_BEAMS=1`); the card
  recommends beam 5, which is slower. Torch's native ops JIT a Triton helper, so a small **exec
  tmpfs `/cache`** holds Triton's kernels (never audio); `/tmp` stays noexec.
- Not done: the eval's vLLM path for these models (8.6–11.3 GB each) — far too big for the memory left.

### API (all Bearer auth; OpenAI shape kept)
- `POST /v1/audio/transcriptions`, `model`:
  - `auto`: route per chunk. Silero VAD first: no speech → `text: ""`, no model run.
    `language` given as `si`/`ta`/`en` → that route, no detection. Otherwise large-v3
    `detect_language` (VAD'd, first 30 s), probabilities **restricted to si/ta/en and
    renormalised** (large-v3's own top guess for Sinhala is often Bengali); best ≥
    `WHISPER_ROUTE_MIN_P` (0.5) → route, else large-v3 with its own detection
    (`reason: low_confidence`). If the routed model can't load (memory floor) → large-v3 with the
    detected language (`fallback: memory`).
  - any alias above (or `whisper-1` = default) → that model; `language` is forced to the model's
    own language for the si/ta models. 503 if it can't be loaded for memory.
  - `json` for `auto`: `{"text", "model", "language"}` (`model` = what really ran, for `made_by`).
    `verbose_json`: as before plus `model`, `model_processing_s`, `load_s` and, for `auto`,
    `routing: {reason, language, probability, probs{si,ta,en}, raw_probs, whisper_top,
    whisper_top_p, detect_s[, fallback]}`. Segments are empty for tamil-asr-qwen3.
- `POST /v1/audio/compare`: multipart `file`, optional `language`, `models` (comma list; default
  all), `prompt`. Runs detection, then every model **sequentially** (one compare at a time;
  compare-only models are unloaded right after use). Returns `{duration, detected, routed_model,
  results: [{model, text, language, processing_s, load_s, routed} | {model, error}],
  processing_s}`.
- `GET /v1/models`: every alias with `role`, `language`, `loaded`, `est_mb`, plus `auto` with its
  routes and `memory: {budget_mb, min_available_mb, available_mb}`.

### Memory (measured 2026-10-12 next to risi-l1, nvidia-smi per process + host MemAvailable)
`CT2_CUDA_ALLOCATOR=cuda_malloc_async` (frees instead of caching) and int8_float16 for large-v3
cut the idle service from 7.3 GB to 2.9 GB, and large-v3 got faster (0.53 s vs 0.70 s, JFK).

| Model | GPU (unified) MiB | host MemAvailable drop | warm latency (clip) | load |
|---|---|---|---|---|
| whisper service idle (large-v3 int8 loaded) | 1 998 | 2.9 GB (old float16 service: 7.3 GB) | — | 3–4 s at start |
| + large-v3 after use | +198 | +0.4 GB | 0.53 s model / 0.85 s request (11 s en) | — |
| + whisper-small-sinhala | +672 | +0.8 GB | 0.37 s model / 0.7 s request (5.2 s si) | 0.3 s |
| + tamil-asr-qwen3 (bf16) | +4 617 | +6.3–6.6 GB | 3.4 s model / 3.8 s request (7.8 s ta) | 1.2 s warm, 7–8 s cold |
| whisper-large-v3-sinhala (int8, compare) | +1 920 | ~+2.2 GB | 1.0 s (5.2 s si) | 1.3–1.7 s |
| large-v3-turbo (fp16, compare) | +2 114 | ~+2.4 GB | 0.24 s (11 s en) | 0.9–1.6 s |

- **All three routed models resident: ~11 GB** of host memory (GPU 7.5 GB + ~3 GB host side:
  torch/transformers libraries and shared memory). risi-l1 holds 47.5 GB GPU and is untouched.
- MemAvailable with risi-l1 running and whisper stopped swung between 16 and 18 GB today (Gradle
  daemons from the other sessions take 4–7 GB each). With everything loaded it fell to 3.4 GB,
  and once to 1.8 GB when another Gradle daemon started; whisper was restarted to give the
  memory back, and the pool now does that by itself (below).
- **Pool rules** (env, `infra/docker-compose.whisper.yml`): lazy loads; the detector is never
  unloaded; a load is refused if the loaded models' estimates would pass
  `WHISPER_MEM_BUDGET_MB` (11 000) or host MemAvailable would fall below
  `WHISPER_MIN_AVAILABLE_MB` (3 072) — LRU models are unloaded first; every 10 s idle models are
  unloaded (tamil-asr-qwen3 after `WHISPER_IDLE_UNLOAD_S`, 900 s; compare-only ones after 120 s),
  and while MemAvailable is under the floor every unused model except the detector is unloaded.
  So Tamil may answer through large-v3 (`fallback: memory`, CER 12 % on the FLEURS clip) when
  the host is busy, and risi-l1 is never starved.
- `mem_limit` 6g → **8g** (host-side RAM only; torch adds ~2 GB anon/shmem, and model-file page
  cache counts here; 6g hit the limit with reclaim). No raise near 16 GiB was needed.

### Routing and quality (`scripts/asr-smoke`, `--manifest ~/risime-eval-data/manifest.jsonl`)
- Test clips (the repo's three Opus clips): si → whisper-small-sinhala, CER 3 %; ta →
  tamil-asr-qwen3, CER 11 %; en → large-v3, exact. Detection: si p = 0.92, ta 0.997, en 0.9999,
  0.19–0.2 s. Silence → empty text in 0.12 s.
- 100 eval clips (50 YouTube Sinhala, 50 FLEURS Tamil, read/broadcast speech; not in the repo):
  **routing 96 %** (ta 49/50, si 47/50: 2 → ta, 1 → en). Mean CER through `auto`: **ta 8.0 %**
  (large-v3 was 23.4 % on the same set), **si 12.4 %** (large-v3: 92 %). No English set was
  available offline beyond the JFK clip (no TTS on spark2), so English routing is checked on that
  clip only.
- Compare on the si clip: kasunw large-v3-sinhala CER 0 %, small 3 %, large-v3/turbo wrong script.
- Concurrency: 6 parallel mixed requests: si/en 1.4–6 s; two Tamil chunks at once take 8–11 s,
  because generation on one Qwen model isn't batched. Fine for 1–2 Tamil calls; 4 concurrent Tamil
  calls with 15 s chunks would lag (follow-up: batch Tamil chunks, or a static-cache compile).
- Per-chunk, not per-word: a 10–15 s chunk gets one language. Code-mixed Singlish/Tanglish chunks go
  to the majority language.

### Privacy (unchanged, verified)
Audio is decoded from the request body in memory and the upload file is closed at once (Starlette
spools only bodies > 1 MB, into the `/tmp` tmpfs). `scripts/asr-smoke` checks that `docker diff`
is unchanged by a run, that `/tmp` and `/cache` hold only known caches (CUDA JIT, Triton,
onnxruntime's id files), and that no file there starts like audio (Ogg, RIFF, FLAC, MP3, WebM).
Logs carry metrics only (model, route reason, language, seconds).

## Amendment 2026-10-12 (b): force Sinhala script (Harsha, PROTOCOL v1.40)
Whisper decoders sometimes answer Sinhala speech in Latin letters (romanised) or in another script.
- **Prompt + language:** a chunk routed to `si` (detected with p ≥ 0.5, or `language=si`) runs
  with `language=si` and a short neutral Sinhala-script initial prompt (`WHISPER_SI_PROMPT`,
  default "මෙය සිංහල කතාබහකි." = "This is a Sinhala conversation."). A caller's own `prompt`
  replaces it. An explicitly named model with `language=si` gets the same prompt and check, but
  is never swapped.
- **Check:** `romanised` = the text has letters but no character in U+0D80–U+0DFF (so Tamil or
  Bengali script counts too); `script: {expected: "sinh", sinhala_chars, latin_chars, ok}` with
  `ok = !romanised` (no letters is ok; code-mixed Sinhala with English words is ok).
- **One retry** (`model=auto` only): the first of `SI_RETRY_ORDER` = `whisper-large-v3-sinhala`,
  `whisper-small-sinhala` that is not the model that just ran, is served and fits memory
  (`NoMemory` → the next). So small → large-v3-sinhala (int8, ~2.2 GB, unloaded right after);
  large-v3-sinhala → small; large-v3 (memory fallback) → large-v3-sinhala, else small. When
  large-v3-sinhala doesn't fit after small, there is no other Sinhala model: no retry, reported
  `romanised: true`. The retry's answer replaces the first unless it is empty. `verbose_json` adds
  `script`, `script_ok`, `romanised` (of the final text), `retried_with` and `first_model`; `json`
  is unchanged.
- **Compare:** when the chunk is `si`, every model runs with `language=si` and the prompt (no
  retry: compare shows each model as it is) and each result gains `script` and `romanised`.
- **Smoke** (`scripts/asr-smoke`): the si clip through `auto` must be Sinhala script (39 Sinhala /
  0 Latin chars, no retry); compare on it fails if a Sinhala-tuned model is romanised; the retry
  order is exercised in the container with a fake runner whose first output is forced Latin (no
  live test hook exists in the service).
- Measured on the si clip (compare, all with `language=si` + prompt): large-v3-sinhala CER 0 %,
  small 3 %, large-v3 now in Sinhala script (was the wrong script) but CER 90 %, turbo Sinhala
  script but garbage (CER 179 %), tamil-asr-qwen3 Tamil script (`romanised: true`).
- Image `risime/whisper:ct2-4.8.2-fw-1.2.1-asr3` (only `server.py` changed). Rollback: `image:`
  back to `…-asr2` (kept on disk) with the previous `server.py`; the app server treats the new
  fields as optional.

## Amendment 2026-10-12 (c): Sinhala route from a held-out eval (Harsha: "Sinhala poor")
- **Why:** the 2026-10-10 Sinhala numbers (whisper-small-sinhala 14.5% WER) came from a YouTube
  set that likely overlaps its training data. `scripts/asr-eval` now scores each model only on clips
  outside its training data (manifest `in_training_of`), through this service, in ≤ 15 s chunks.
  Results and sets: docs/RISI-MODELS.md, "ASR eval 2026-10-12".
- **Route:** `si` → **`qwen3-asr-0.6b-sinhala`** (Nerdstorm/Qwen3-ASR-0.6B-Sinhala rev 2, MLX 8-bit
  dequantised to bf16 by `convert_models.py`, loaded by `qwen3_asr.py` with the forced
  "language Sinhala" prefix). Held-out spontaneous Sinhala: CER 13.3% vs 20.4% for the previous
  route; conversational (5 held-out YouTube channels): 21.2%, the best of all candidates; it keeps
  English words in English letters. On read speech the small model stays better (5.2% vs 8.9%).
  Licence CC BY-SA 4.0 (served, not redistributed). ~3.5 GB resident, RTF ~0.2 (≈3 s per 15 s
  chunk, vs 0.5 s), unloaded after `WHISPER_IDLE_UNLOAD_S`.
- **Fallback:** `whisper-small-sinhala` stays loaded (`WHISPER_KEEP`) and is the script retry
  (`WHISPER_SI_RETRY_ORDER=whisper-small-sinhala,qwen3-asr-0.6b-sinhala`) and the **memory
  fallback**: a NoMemory on the routed Sinhala model now goes to the first fitting model of the
  retry order before large-v3 (whose Sinhala is unusable). `routing.fallback_model` names it.
- **Compare** without a models list runs the set for the detected language (routed model first):
  si: Qwen, small, `omnilingual-ctc-1b`; ta: tamil-asr-qwen3, `whisper-tamil-medium`,
  `omnilingual-ctc-1b`, large-v3; en: large-v3, turbo (`WHISPER_COMPARE_SI|TA|EN`).
  `/v1/models` lists `compare_sets` and `si_retry_order` on the `auto` entry.
- **New compare-only models** (in `~/risime-models`, served when present): `omnilingual-ctc-1b`

## Amendment 2026-10-14 (e): omniASR as an eval / compare-only service (Harsha Part 12)
- **What:** `risime-omniasr` (`infra/omniasr`, `infra/docker-compose.omniasr.yml`, 127.0.0.1:8210):
  Meta Omnilingual ASR (Apache-2.0) on fairseq2 0.6 (MIT), built from source for aarch64 against the

  patches; keeping it out of risime-whisper means the production speech image and its memory pool
  are unchanged.

  (decision 085); omniASR is one more tool it can be scored with (eval: `scripts/asr-eval` sets,
  the new real Singlish set; promotion only by the decision 084 rule).
- **Result:** no route change. Numbers, memory and caveats: docs/status/asr-omni-eval-2026-10-14.md.

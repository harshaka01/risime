# 071 — Self-hosted speech-to-text for Risi call transcription (faster-whisper on 127.0.0.1:8200)
**Status:** accepted 2026-10-09 (root). Implements the infra part of decision 070 (§27.7–27.9:
Risi listening to Official calls). The speech model is named in `made_by.also` as
`faster-whisper-large-v3` (provider `risime`, task `transcribe`).

## Decision
- **Engine:** faster-whisper 1.2.1 on CTranslate2 4.8.2, **built from source with CUDA for the
  GB10** (sm_121, aarch64). PyPI's aarch64 `ctranslate2` wheels are CPU-only.
  - **Build flags:** `-gencode=arch=compute_121,code=sm_121` is patched in, because CMake's
    FindCUDA arch table doesn't know 12.1. The build uses `WITH_CUDNN=OFF`, `WITH_MKL=OFF`
    and `WITH_RUY=ON`.
  - **Why no cuDNN:** CTranslate2's cuDNN Conv1D uses the legacy API with fixed algorithms, and
    cuDNN 9.26 answers `CUDNN_STATUS_NOT_SUPPORTED` on sm_121. Without cuDNN, CTranslate2 uses its
    own im2col + cuBLAS Conv1D. Whisper has only two conv layers, so this costs nothing measurable.
  - **`av==15.1.0` is pinned**, because PyAV 16+ dropped the `metadata_errors` argument that
    faster-whisper 1.2.1 passes.
- **Image:** `risime/whisper:ct2-4.8.2-fw-1.2.1`, built locally by
  `infra/whisper/Dockerfile`, in two stages, on `nvcr.io/nvidia/vllm:26.09-py3`. That base has
  CUDA 13.4, Python 3.12 and ffmpeg.
  - **Why this base:** it is already on spark2 for `risi-l1` (decision 061). Its layers are
    shared, so the image adds about 0.3 GB of disk, not 26 GB, and needs no new pull. It also
    carries the build toolchain and vLLM's Whisper serving (the fallback below).
  - **Server:** `infra/whisper/server.py`, a small FastAPI app.
- **API** (OpenAI-compatible):
  - `POST /v1/audio/transcriptions` takes multipart `file`, `model`, `language`, `prompt`,
    `response_format` (`json`, `text` or `verbose_json`), `temperature`, and `vad_filter` (an
    extension, default true).
    - `verbose_json` adds `language_probability`, `duration`, `duration_after_vad`, `segments`
      (with `avg_logprob` and `no_speech_prob`) and `processing_s`.
    - `model` must be the alias or `whisper-1`.
  - `GET /v1/models` (with the key) lists the alias.
  - `GET /health` needs no key.
  - Every other call needs `Authorization: Bearer $WHISPER_API_KEY`. The key lives in `.env`,
    is generated by `scripts/whisper-smoke --init-key` (or was added by root on spark2) and is
    never printed.
  - The upload limit is 25 MB.
- **Model:** `large-v3` as CTranslate2 float16 (`Systran/faster-whisper-large-v3`, MIT), in
  `~/risime-models/faster-whisper-large-v3`, mounted read-only.
  - The alias `faster-whisper-large-v3` is served.
  - Beam size is 5. `condition_on_previous_text` is off, because calls arrive as ≤ 30 s chunks.
  - The Silero VAD filter is on.
  - **Faster option:** `large-v3-turbo` (`mobiuslabsgmbh/faster-whisper-large-v3-turbo`, MIT,
    already in `~/risime-models/faster-whisper-large-v3-turbo`).
    - Measured on the JFK clip: 0.38 s against 0.72 s for large-v3, with the same English text.
      It is about 1.4 GB smaller.
    - Its Sinhala and Tamil are expected to be no better.
    - To switch, set `WHISPER_MODEL_DIR=faster-whisper-large-v3-turbo` and
      `WHISPER_MODEL_ALIAS=faster-whisper-large-v3-turbo` in `.env`, then `up -d`. The alias is
      what `made_by` and the learning log show, so it must name the real model.
  - `WHISPER_COMPUTE_TYPE=int8_float16` gave the same English text, at 0.69 s, with less memory.
- **Network and privacy:**
  - `127.0.0.1:8200` only (rule 6), with no Caddy route. The only client is the app server's
    `risi-listen` path.
  - `HF_HUB_OFFLINE=1` and a local model path (`local_files_only`) mean nothing is fetched at
    runtime.
  - Audio is decoded in memory and never written. `/tmp` is a 256 MB tmpfs.
  - The root filesystem is read-only. The service runs as uid 1000, with `cap_drop: ALL` and
    `no-new-privileges`.
  - The access log is off, and faster-whisper's own logger is at WARNING. The service logs
    metrics only: audio seconds, processing seconds, detected language and segment count. It
    never logs text or prompts (decision 066).
  - The container stays on the default bridge network, because an `internal` network can't
    publish a port. It makes no outbound calls.
- **Concurrency:** `WHISPER_NUM_WORKERS=2`, so two transcriptions run in parallel on the GPU and
  more requests queue. With `RISI_LISTEN_MAX=4`, this is enough (see the latency numbers below).

## Memory (measured on spark2, 2026-10-09, next to the running vLLM `risi-l1` at 0.34)
| State | `free -m` available | GPU (nvidia-smi, whisper) | container RSS |
|---|---|---|---|
| whisper down | 33 770 MB | — | — |
| whisper up, idle (model loaded) | 28 011 MB | 4 447 MiB | 0.5 GB |
| after smoke + 8 parallel requests | 26 880 MB | 6 553 MiB | 1.1 GB |

- **Total cost:** about **7 GB**, unified memory (GPU and host share the 121 GB).
- **Headroom:** about 27 GB of RAM stays available, which is more than the 24 GB that
  decision 061 asks to keep for the pilot. The two coexist, and `scripts/llm-smoke` passed both
  before and after whisper started, with the same numbers: JSON extraction in 4.3–4.6 s,
  ~4.9k-token summary in 9.4–9.6 s, decode 50.2 tok/s.
- **Limits:**
  - `mem_limit: 6g` caps host-side RAM (Python, decoding, buffers).
  - CUDA allocations on the GB10 are driver-allocated unified memory outside the cgroup, so
    the GPU share is bounded instead by the model size plus CTranslate2's caching allocator.
    That allocator is capped at 1 GiB of freed blocks
    (`CT2_CUDA_CACHING_ALLOCATOR_CONFIG=4,3,12,1073741824`).
- **If memory gets tight:**
  - first switch to `int8_float16` or turbo, which saves about 1.5–3 GB;
  - then stop whisper (`docker compose -f infra/docker-compose.whisper.yml stop`). The server
    then answers `risi: unavailable` (§27.7).

## Latency (measured, `scripts/whisper-smoke` and a parallel test)
- **English** (11.0 s JFK clip, Opus 24 kbit/s): 0.92–0.95 s end to end, RTF 0.085, exact
  transcript. The model loads in 2.7 s, and the container is healthy about 10 s after `up`.
- **Parallel** (11 s clip): 4 requests take 2.45 s wall (max latency 2.44 s); 8 requests take
  4.94 s wall (max 4.94 s). At 4 listened calls with ≤ 30 s chunks this stays far ahead of real
  time.
- **Tamil** (FLEURS `ta_in`, 7.8 s, read speech): 2.6–2.9 s, **CER 12 %**, both with
  `language=ta` and with auto-detect (detected `ta`, p = 0.97). The text is readable; errors are
  mostly vowel signs and consonant confusions (அழைக்கப்படுகிறது → அளைக்கப்படிகிறது).
  Good enough to extract follow-ups from.
- **Sinhala** (OpenSLR SLR30, 5.2 s, read speech): **unusable.**
  - With `language=si`: CER ~100 %, the wrong words, and 5.5 s because of temperature fallbacks.
  - With auto-detect, it detected **Bengali** (p = 0.33) and transcribed into Bengali script.
  - **Consequences:**
    - the app server must pass `language` when it knows it;
    - Sinhala speech should not be summarised from this model;
    - a Sinhala-finetuned Whisper, or a different model, is follow-up work (a decision
      amendment, not a contract change).
- These are single-clip spot checks of read speech. Real call audio (crosstalk, Singlish /
  code-mixing) will be worse.

## How to update
- **Model:** download into `~/risime-models/<dir>` (CTranslate2 format), set `WHISPER_MODEL_DIR`
  and `WHISPER_MODEL_ALIAS` in `.env`, then run
  `docker compose --env-file .env -f infra/docker-compose.whisper.yml up -d` and
  `scripts/whisper-smoke`.
- **CTranslate2 / faster-whisper:** bump `CT2_VERSION` / `FASTER_WHISPER_VERSION` in the
  Dockerfile. Re-check:
  - the sm_121 sed;
  - whether cuDNN Conv1D works (try `WITH_CUDNN=ON`);
  - the `av` pin.

  Then `up -d --build` and run both smokes.
- **Base image:** when `risi-l1` moves to a newer `nvcr.io/nvidia/vllm` tag, move `BASE` with
  it so the layers stay shared, and rebuild.
- `restart: unless-stopped`. The first build takes about 10 minutes (CTranslate2 compile, 20
  cores); later builds use the cache.

## Fallback (as decision 070 allows)
If the CTranslate2 CUDA build breaks on a future base, serve Whisper with vLLM instead:
- `vllm serve /models/whisper-large-v3 --served-model-name faster-whisper-large-v3`, from the same
  NGC image. That needs the HF-format `openai/whisper-large-v3` weights in `~/risime-models`;
  they are not downloaded yet.
- It has the same OpenAI `/v1/audio/transcriptions` endpoint on 127.0.0.1:8200 with
  `VLLM_API_KEY=$WHISPER_API_KEY`, and a small `--gpu-memory-utilization` (~0.06). Re-measure
  next to `risi-l1`.

The alias must then name the real model (e.g. `whisper-large-v3-vllm`). That would be an
amendment to this decision, not a contract change. vLLM's endpoint has no VAD and no
`verbose_json` segment confidences.

## Test data
`infra/whisper/testdata/` holds three Opus clips, 71 KB in all; their sources and licences are in
its README:
- English: JFK 1961, public domain;
- Sinhala: OpenSLR SLR30, CC BY-SA 4.0;
- Tamil: FLEURS, CC BY 4.0.

No offline TTS is installed on spark2, and real speech is the better test anyway.
`scripts/whisper-smoke`:
- asserts the bind, auth, the English words and latency ≤ `WHISPER_SMOKE_MAX_S` (default 5 s);
- reports the Sinhala and Tamil CER as information only.

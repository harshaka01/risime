# Brief v1.31 (android): Google Calendar link (PROTOCOL.md §31)

For the **android** role. Contract: `contract/v1/PROTOCOL.md` v1.31 §31 and the "(v1.31)" notes in
§25.3, §29.1 and §29.7. Decision 074. Commit only `android/` and `docs/status/android.md`.
Gate: `./gradlew assembleDebug testDebugUnitTest` (spark2 uses the aapt2 override from
`~/.gradle/gradle.properties` only).

**The rules to keep in mind:**
- The Google token stays on this phone, in memory only. It never goes to disk, a log, a backup, a
  push or the RisiMe server.
- Google calendar names, Google ids and Google event titles also stay on the phone.
- The phone sends the server busy blocks, local `ref`s and counts only.
- RisiMe changes only the Google events it created. These carry the tag `risime=1`.

## For root: `scripts/fake-gcal` and `ui-entry-test --google` (Android does not write these)
`scripts/fake-gcal` is specified in §31.11: Python, loopback only, `--port 8198 --token T --record
file`. It provides `/_control`, `/_seed` and `/_events`. The server runs with `RISI_EVENTS=on
RISI_GCAL=on` and fake-llm `--script`. A is two devices (A1 = the Google device, A2), and B is a
second user. Redroid has no Play services, so the seam is used.

1. Start fake-gcal. `adb reverse tcp:8198 tcp:8198` on A1.
   `adb shell am broadcast -a lk.codegen.risime.debug.GCAL_TEST --es base_url
   http://127.0.0.1:8198/ --es access_token T --es account a@test --es state connected`.
   Seed the calendars "Work" (primary, owner) and "Personal" (owner), and "Holidays" (reader,
   hidden).
2. Switch off first (`RISI_GCAL` unset): the section is absent and the "Am I free" line is
   exactly the v1.30 one.
3. Restart with `RISI_GCAL=on`. On A1, Settings → Risi skills → Calendar → [Connect Google
   Calendar]. The picker shows the 3 calendars, with Work and Personal ticked by default. Write
   to Work. Check `GET /risi/calendar/google`: `connected`, 2, A1's id. Check that the server DB
   holds no "Work" or "Personal".
4. Seed a busy event "CANARY-GTITLE" on Work, Mon 14:00–15:00. In A2's Risi chat ask "Am I free
   Monday 2pm" → "not free … 1 busy time", and "Checked: Risi Calendar · Google Calendar (2
   calendars)". The same message on A1 reads "Google Calendar (Work, Personal)". Screenshot
   both.
5. Stop A1's container. Ask again on A2 → "Not checked: Google Calendar (phone didn't answer)",
   never "free". Start A1 again.
6. On A1, [Add] a Risi event Tue 10:00. fake-gcal `/_events` has one event with `id` `risi<hex>`,
   `risime=1`, no attendees, and `sendUpdates=none` in the record. Move it in RisiMe → `PATCH`.
   Delete it in RisiMe → `DELETE`. Re-add and force a retry → still one event.
7. Loop guard: with the copy in Google, "Am I free Tue 10am" counts one busy time.
8. `/_control revoked` → the next read gives "needs reconnecting", one `google_reconnect` card in
   the Risi chat, and the section shows [Reconnect]. Broadcast the seam with `connected` →
   [Reconnect] → reads work.
9. On A2, Disconnect with [Remove them from Google] → A1 deletes the copies, `gcal_*` is empty,
   and the link is `not_connected`.
10. Canaries: "CANARY-GTITLE", the token `T`, "Work" / "Personal" and `a@test` must not appear in
    the server log, the Postgres/Cassandra dumps, `risi_turn_steps`, the fake-llm record or
    logcat (release-mode tags). The release-dex check passes. The upgrade gate (hard rule 9)
    shows no lost messages.

   Both permissions are ticked.

# RisiMe v0.2.0-nightly.8 — end-to-end encryption on (required update)

Wire protocol: `contract/v1/PROTOCOL.md` **v1.7**. Server: https://risime.risicloud.ai.
**This update is required.** Older apps are blocked until they update (one tap).

## New
- **End-to-end encryption is switched on (decision 038).**
  - Each chat upgrades automatically once both people are on this version.
  - Encrypted chats show 🔒 "End-to-end encrypted".
  - Until the other person updates, a note says "Not end-to-end encrypted yet: <name> needs to
    update".
  - The server stores only ciphertext for encrypted chats.
- The app pins the server's attestation key (kid `x-nu0EBHzGv-…`). Every device in an encrypted
  chat is vouched for by the server and verified on your phone.
- The "Dev build" banner stays until every chat is encrypted and the rollout is recorded.
- **Encrypted messages use a typed envelope** (`{"v":1,"type":"text",…}`). Later features
  (reactions, groups, images) add types that this version safely ignores, so they need no further
  forced update.
- The e2ee ciphertext cap is 24 KiB, so maximum-length texts fit when encrypted.

## Fixed before release
- An app crash that would have happened the moment E2EE switched on: the upgrade ran database work
  on the main thread.
- MLS engine access is serialised per device (defence in depth). A concurrency stress test is
  added, and a native SQLite crash in the JVM test helper is fixed.

## Verification
- **Gates:** server, Android and crypto.
- **Live interop:** 32 checks, including 9 real-MLS E2EE checks, green in repeated runs.
- **Concurrency stress test:** 5 rounds × 64 concurrent engine calls, green.
- **Pinned key:** the release APK carries the pinned attestation kid (checked by the release
  script).

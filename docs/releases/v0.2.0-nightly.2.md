# RisiMe v0.2.0-nightly.2

Nightly build from `main`. Wire protocol: `contract/v1/PROTOCOL.md` **v1.3**. This is the first
build of the RisiCloud phase (decisions 013–019).

## New
- **Sign-in through RisiCloud** (Keycloak realm `aoa`, client `risime`):
  - AppAuth with PKCE, using a browser tab;
  - the refresh token is unlocked by **fingerprint**, or by device PIN on Android 11+;
  - logout revokes the offline token and ends the Keycloak session.
  - **Dormant until the Keycloak client exists.** The server must advertise `oidc` in
    `/auth/config`. Until then the app uses the dev OTP login, as before.
- **Identity stays phone-first.** Your RisiMe user and phone come from the allowlist, which is now
  keyed by email as well. Unknown emails see "not on the allowlist"; a phone already linked to
  another RisiCloud account shows a conflict screen.
- **In-app updater** (release builds only):
  - checks `https://risicloud.ai/app/risime/version.json`;
  - verifies the sha256 and the signing certificate before installing;
  - blocks the app when an update is `required`.
- **Realtime:**
  - the token is sent in the `Authorization` header, not the URL;
  - silent token refresh (`auth:refresh`);
  - an expired session reconnects instead of logging out.
- **No more data wipe on auth trouble.** A 401 never deletes local chats. Only logout, a server
  switch, or a different user signing in does.
- **The release build's default server URL is now `https://risicloud.ai/risime`** (option 2b).
  That route isn't switched on yet. Fresh installs should set the server in
  "Server · Change" on the login screen; existing installs keep their setting.

## Server
- Keycloak JWT verification against the realm JWKS (cached, fail-closed, with every claim rule of
  v1.3 §6.0). Mapping to allowlisted users. `403 not_allowlisted`, `409 identity_conflict`.
  `mix risime.allow --rebind`.
- `OIDC_ENABLED` is off by default. `DEV_LOCAL_AUTH` is on in dev/test, off in prod.
- Prod: no `force_ssl` redirect; `check_origin` limited to risicloud.ai; URL path `/risime`.

## Release tooling
- `scripts/publish-release` and `nightly-release` publish the last five APKs, `version.json` and
  a "Get RisiMe" page to `risicloud.ai/app/risime/` over an upload-only rrsync key.
- `infra/risicloud/Caddyfile.risime`: the option 2b routes, prepared and validated but off.
- `scripts/build-rust-android`: builds and checks the E2EE `.so` natively on spark2.

## Verification
- **Server gate:** 140 tests, 0 failures.
- **Android gate:** 98 tests, debug and release builds.
- **Crypto gate:** 11 tests.
- **Live v1.3 interop:** the Android JVM clients against a `main` server, using a **local
  stand-in issuer** (its own RSA key and JWKS, with Keycloak-shaped tokens; the real `risime`
  client doesn't exist yet).
  - `auth/config` lists both modes.
  - First-use mapping creates users from the allowlist; a non-allowlisted email → 403.
  - A non-allowlisted socket upgrade → 403.
  - Messages over Bearer JWT sockets are delivered.
  - `auth:refresh` works for the same user and returns `identity_mismatch` for another.
  - A token expiring during a live session leads to `auth:expired`, a forced refresh, Live again,
    and delivery after.
- **Not yet verified:** a real Keycloak token, and any of the new code on a device (steps 18–24
  in `docs/status/android.md`).

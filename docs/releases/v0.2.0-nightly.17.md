# RisiMe v0.2.0-nightly.17 — photos and "needs to update" fixed, emoji, groups

Wire protocol: `contract/v1/PROTOCOL.md` v1.13 (a §12.1 clarification, no wire change). Server:
https://risime.risicloud.ai. **Not a required update.**

## Important: update, never uninstall
Always update **over** the old app (Settings → Update, or open https://risicloud.ai/app/risime/ in
your phone's browser and install over it). **Never uninstall or clear the app's data**: that makes
your phone a new device. Groups then have to re-add it, and old messages can't be read on it.

## Fixed
- **"<name> needs to update" when they're already up to date:**
  - A reinstalled phone left its old install registered, and the server kept counting it.
  - Old installs no longer count once a newer one exists.
  - The app now says the real reason ("<name>'s phone can't receive photos yet", "can't take
    calls yet", "hasn't registered encryption keys yet") and says "needs to update" only for a
    really old app.
- **Photos couldn't be sent:** the attach button was off because of that same old-install problem.
  It works again.
- **Calls readiness:** the app now re-registers what it can do whenever that changes. For example,
  once you allow notifications, calls work without restarting.
- **Emoji:** the picker stays open, so you can add several emoji; ⌫ deletes one whole emoji.

## Groups that "disappeared" after nightly.16
- Nobody was removed on the server. Phones that were reinstalled became new devices, and a new
  device has to be re-added by an admin whose phone is already in the group.
- The group comes back as soon as one admin opens RisiMe. The admin can also tap **Reset
  encryption** in the group (that loses older messages).
- A normal update keeps groups: tested by updating nightly.12 directly to nightly.16, with the
  device id kept.

## Verification
- Gates: server, Android, crypto.
- Live interop: a nightly.16-style reinstall is ready in DMs and groups, photo upload works end to
  end, groups survive an update.
- Automatic upgrade gate on spark2 (Redroid): the published nightly.16 is upgraded in place to this
  build, with messages kept, **the device id kept**, no sign-in, and new messages delivered.

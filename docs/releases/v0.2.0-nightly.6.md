# RisiMe v0.2.0-nightly.6

Wire protocol: `contract/v1/PROTOCOL.md` **v1.7**. Server: https://risime.risicloud.ai. No
user-visible behaviour changes for current chats: E2EE and push are built but **dormant**.

## New (dormant until switched on)
- **End-to-end encryption groundwork (0.3, contract v1.7):**
  - server: device attestation, key packages, MLS groups with epoch compare-and-set, the commit
    log, ciphertext-only messages and the device census;
  - app: an MLS key store sealed inside the message database (crash-safe, decision 033), ordered
    sync, an encrypt-at-send outbox, and the lock and "needs to update" UI, running against a test
    engine;
  - the crypto core: a persistent store, attested leaves, and commits applied only after the
    server accepts them.
  - **E2EE stays off on the pilot:** without the attestation key, MLS endpoints answer
    `mls_unavailable` and the app behaves exactly as before. The dev banner stays.
- **Push notifications client (contract v1.5):** local, content-free-to-Google notifications.
  **Off** until the Firebase files exist.
- **App:** the socket now reports `device_id` and `app_version` (the census used for E2EE
  readiness).

## Verification
- **Gates:** server 265 tests, Android 155 tests (debug and release builds), crypto 47 tests, plus
  the Android and host builds of the MLS core.
- **Live interop:** 23 checks with real Android clients against a temporary server from `main`,
  covering chat, presence, typing, the JWT path, a real token expiry and the friends flow.
- **Load test:** plain p99 7.4 ms; `--e2ee` mode p99 21 ms (200 users).

# Review: encrypted backups v1.22, android side

**Reviewer:** android (root acting as reviewer), 2026-10-08.
**Proposal:** `contract/proposals/2026-10-08-backups-v1.22.md`.
**Verdict:** accept with A1–A9 (folded into §22.5–§22.7).

## Required changes
- **A1. The empty-install trap.** A fresh install that backs up before restoring would replace the
  good backup. Rule: no server backup until the user restored or explicitly skipped; replaced
  backups stay 7 days as a second net.
- **A2. Before the in-app update** the app must finish a local backup and, with server backup on,
  the upload (2-minute cap, then ask) before starting the installer; on an installer failure it
  says "Don't uninstall" and offers "Back up now". This targets P0-2 finding 1 directly.
- **A3. Before a confirmed wipe** a backup is mandatory (uploaded, or offered as a file); the wipe
  then removes app-private backups and `BK` too (it is "delete from this phone").
- **A4. Streaming export.** Build JSON Lines per conversation in a read transaction, feed
  `Deflater(nowrap)` and the core writer in chunks; never hold the bundle in memory, never write a
  plaintext temp file. WorkManager with `setForeground` (`dataSync`) for large backups.
- **A5. Restore is resumable** (progress per `backup_id` and line) and idempotent (unique
  `message_id`); one transaction per ≤ 1 000 lines; it never deletes or replaces a row (rule 9).
- **A6. Order with the first join.** Restore before the first join is nicer but not required; the
  §13.3 extension (a restored `message_id` adds no marker or gap row) plus the §17.12 marker update
  make both orders converge.
- **A7. Recovery-key UX.** Show once at setup with Copy (clip marked sensitive) and a re-type check
  of the last group; viewable again behind the device credential (the device already holds `BK`,
  so this adds no exposure); input normalisation as §22.2.
- **A8. Turning on can't be silent** (only the user can keep the secret); offer it after the update
  and with a dismissible chat-list card. Local backups need no user action (a silent local `BK`).
- **A9. Restored rows** are never notified, unread or acked; outgoing keep their status; images by
  reference (full images only while the original blob lives; the thumbnail always).

## Chunk order (each green on the Android gate)
1. Models and parsing of every v1.22 example; the bundle writer and importer on the JVM with a
   fake cipher (filters, dedupe, deletes win, resume). 2. The core functions through UniFFI and the
   vectors test (after the crypto release). 3. Local backups (daily, pre-update, pre-wipe), export
   and restore from file. 4. Server backups (parts upload, commit, retention UI, recovery key,
   first-sign-in restore). 5. Upgrade-gate scenario with root.
